## 파일 형식 (D-13)

`.howsheet.json`은 **`GuideDocument`를 그대로** 담는다. 픽스처 10종이 이 모양이고
`verify:fixtures`가 고정한다. 봉투로 감싸면 AGENTS.md §7의 "파일 형식" 변경이 된다.

자산 바이트만 문서에 자리가 없다. `assets`는 manifest일 뿐이고 본문은 저장소의
`assets` 테이블에만 있다. §2.4.1이 "Base64 Data URL 또는 별도 자산 맵"을 지정하고
M8 할 일 2가 그 구현을 요구하므로 **최상위 형제 키** 하나를 더한다.

```json
{ "schemaVersion": "1.0", ..., "assetData": { "asset-1": "data:image/png;base64,..." } }
```

**문서 스키마는 손대지 않았다.** Zod가 모르는 키를 strip하므로 이 파일을 그대로
`parseGuideDocument`에 넘기면 `assetData`는 사라지고 정확히 `GuideDocument`만
남는다(단위 테스트로 고정). 자산이 없으면 키를 만들지 않아 자산 없는 가이드의
내보내기 결과는 픽스처와 글자 그대로 같은 모양이다. `SCHEMA_VERSION`을 올릴
이유가 없으므로 STOP 대상이 아니다.

## 결정론 정책 (DoD 2)

두 가지를 고정한다.

1. **키 순서** - 객체 키를 재귀적으로 사전순 정렬한다. 배열은 순서가 의미이므로
   건드리지 않는다. 문서가 IndexedDB 구조화 복제에서 왔는지 `JSON.parse`에서
   왔는지에 따라 삽입 순서가 달라지는데, 정렬하면 출처와 무관해진다.
2. **시간 필드** - 내보내기는 시각을 **찍지 않는다.** `createdAt`·`updatedAt`은
   문서의 데이터라 그대로 옮긴다. 내보낸 시각을 파일에 넣으면 바뀐 것이 없어도
   두 번째 내보내기가 달라져 DoD 2를 만족할 수 없다. 무작위 값도 만들지 않는다.

정렬은 `assets[].width` 같은 optional 키의 **유무**까지 정규화하지는 않는다.
없는 키는 없는 채로 남는다. 왕복에서는 양쪽이 같은 규칙을 지나므로 문제가 되지
않고, 그 이상은 문서를 고치는 일이라 하지 않았다.

## 설계 판단

**가져오기는 언제나 새 가이드를 만든다.** 파일 안의 `id`를 그대로 쓰면
`GuideRepository.save`가 조건 없는 `put`이라 같은 ID의 기존 문서를 덮어쓴다.
DoD 4를 조건부가 아니라 **구조적으로** 만족시키려면 ID를 새로 발급하는 것이
맞다. 자기 백업을 되돌리면 사본이 하나 생기지만, 덮어써서 잃는 것보다 낫다.

**자산 ID도 새로 발급한다.** `assets` 테이블의 기본키는 가이드별이 아니라
**전역**이다. 파일의 자산 ID를 그대로 넣으면 같은 ID를 가진 **다른 가이드**의
자산 행을 덮어쓴다. 이것이 DoD 4의 가장 조용한 위반 경로였다. 이미지 블록의
`assetId` 참조도 함께 옮긴다 - 빠뜨리면 `ASSET_REF_NOT_FOUND`가 된다.

**`AssetRepository.put`을 쓰지 않는다.** 그 함수는 (guideId, checksum)이 같으면
**넘긴 ID를 버리고** 기존 자산을 돌려준다. 업로드에는 옳지만 가져오기에서는
manifest의 두 항목이 하나로 접히면서 한쪽 참조가 깨진다. 트랜잭션 안에서
`tx.assets.put`으로 직접 넣는다.

**디코딩과 체크섬을 트랜잭션 밖에서 끝낸다.** 저장소와 무관한 `await`를 Dexie
트랜잭션 안에서 하면 그 사이에 트랜잭션이 커밋된다. `AssetRepository.put`이
`blob.arrayBuffer()`를 밖에서 끝내는 것과 같은 이유다.

**importer는 저장소를 모른다.** 파일 텍스트를 받아 "무엇을 저장하면 되는지"와
"무엇이 잘못됐는지"만 돌려준다. 순수 함수라 node 환경에서 그대로 돌고, 실제
쓰기는 호출자가 `withSnapshot` 안에서 한다.

**어떤 입력에도 던지지 않는다.** 손상된 파일은 정상적인 결과이지 프로그램
오류가 아니다. 호출자가 이슈 목록을 그대로 화면에 옮길 수 있어야 한다.

**자산 오류는 막고 자산 누락은 막지 않는다.** 본문이 없는 것은 경고다 - 그림
없이도 글은 읽히고 리더에는 이미 "이미지를 불러오지 못했습니다" 상태가 있다.
막으면 이미지를 잃은 사본으로 아무것도 되살릴 수 없다. 반면 체크섬 불일치와
형식 오류는 **error**다. 검증한 적 없는 바이트를 저장소에 넣지 않는다. "없는
셈 치기"는 M8 주의가 금지한 자동 수정이다.

**체크섬을 계산하지 못한 것과 다른 것을 구별한다.** `crypto.subtle`은 보안
컨텍스트에만 있다. 없을 때 불일치로 보고하면 멀쩡한 파일을 손상됐다고 말하는
것이고, 조용히 넘기면 검증한 척이 된다. `ASSET_CHECKSUM_UNVERIFIED`를 따로 뒀다.

**"사용자 행동"에 새 필드를 만들지 않았다.** `ValidationPanel`의
`RESOLUTION_HINTS`가 이미 `Record<IssueCode, string>`이라 **코드를 더하면
컴파일이 깨진다.** DoD 3이 요구하는 행동 문구를 잊을 수 없게 만드는 장치가
이미 있었다. 새 코드 10종의 문구를 채웠고, 빈 문자열까지는 막지 못하므로
"importer가 내는 모든 코드에 비어 있지 않은 행동이 있다"를 테스트로 덧붙였다.

**마이그레이션 레지스트리는 비어 있고, 그래도 DoD 5는 공허하지 않다.**
`SCHEMA_VERSION`이 `'1.0'`이고 그 앞의 공개 버전이 없다. 올릴 대상이 없는데
단계를 만들면 존재한 적 없는 `0.9` 문서를 위한 픽션이 제품에 남는다.
`planMigration`이 레지스트리를 전역이 아니라 **인자**로 받으므로 실행기는 실제
코드이고, 테스트가 합성 레지스트리로 성공·다단계·던짐·경로 없음 네 갈래를 모두
돌린다. 제품 레지스트리가 비어 있다는 사실 자체도 테스트로 고정했다.

## 음성 검증이 잡은 것

세 건이 처음에 물지 않았다. 전부 코드나 단언 쪽 문제였다.

- **높은 major 차단이 중복이었다.** importer가 `unsupportedMajor`를 일찍 막고
  있었는데, `parseGuideDocument`가 파싱보다 먼저 같은 판정을 하고 같은 코드를
  돌려준다. 그 분기를 지워도 아무 테스트가 깨지지 않았다 - 어떤 테스트도 두
  경로를 구별하지 못한다는 뜻이다. **중복을 지웠다.** DoD 6은 도메인이 지키고,
  음성 검증은 "버전 판정을 파싱 뒤로 미루기"로 바꿔 실제로 물게 했다.
- **마이그레이션 원본 보호 테스트가 공허했다.** `structuredClone(raw)`를 지워도
  통과했다. 당연하다 - 입력이 **문자열**이라 호출자가 잃을 객체가 없다.
  §2.3.5의 "복사본" 요구는 이 함수에서 이미 충족돼 있고(우리가 파싱한 결과가
  곧 사본), 실제 원본 보호는 저장소의 `withSnapshot`이 한다. 공허한 단언을
  지우고, 남긴 `structuredClone`이 **관측되지 않는 방어**라는 사실을 코드에
  적었다.
- **롤백 테스트가 2겹 중 1겹만 봤다.** `withSnapshot`은 트랜잭션 롤백과 스냅샷
  복귀 두 겹으로 막는데, Dexie가 알아서 되돌리므로 `rollbackTo`를 지워도
  통과했다. 트랜잭션이 롤백하지 **않는** 백엔드를 넣어 2겹째만 남기는 테스트를
  더했다. 조기 커밋·브라우저 종료가 그 상황이고, 그 대비가 `withSnapshot`의
  존재 이유다.

## E2E 게이트가 침묵하고 있었다

**M7 보고서의 "74 passed (브라우저 3종)"는 틀렸다.** 그때 24건이 실패하고
있었다.

원인은 실행 방법이다. `pnpm exec playwright test 2>&1 | tail -4`로 돌리면
파이프의 종료 코드는 **`tail`의 것**이라 언제나 0이고, 화면에는 마지막 몇 줄만
남는다. Playwright의 실패 요약은 그 위에 있었다. M7에서 이 방식을 썼고, 그래서
"통과"로 기록했다.

JSON 리포터로 다시 세니 **99개 중 24개 실패**였다. 셋을 고쳤다.

1. **M7이 M5 테스트 8종을 깨뜨렸다.** `PreviewPage`를 리더 셸로 바꾸면서
   `preview-step`이 `reader-step`이 되고 시작 화면 게이트가 생겼는데,
   `content-blocks.spec.ts`는 여전히 곧바로 단계를 찾고 있었다. 제품 변경은
   의도한 것이므로 테스트를 새 흐름에 맞췄다. (8종 × 3 브라우저 = 24건)
2. **M7의 이어하기 테스트가 거짓 통과였다.** 저장이 끝났는지를 "본문에 단계
   ID가 들어 있는가"로 봤는데, `activePath`가 경로의 **모든** 단계 ID를 담아
   첫 저장부터 참이었다. 그래서 디바운스가 끝나기 전에 새로고침했고,
   **webkit에서만 재현되는 실패**로 드러났다. 커서 필드만 보도록 고쳤다.
3. **Firefox 경합.** 자동 저장 완료를 기다리는 5초 예산이 워커 4개에서
   브라우저 기동 경합만으로 넘어갔다. 실행할 때마다 다른 테스트가 하나씩
   실패했다. 이 값은 제품 계약이 아니라 하네스 예산이다 - 500ms 목표와 1초
   하드 상한은 가짜 시계를 쓰는 `tests/unit/autosave`가 판정한다. 예산을
   15초로 올리고 그 사실을 상수 주석에 적었다.

지금은 **99개 전부 통과하고 종료 코드가 0이다.** 연속 두 번 확인했다.

앞으로 E2E는 파이프로 감싸지 않는다. 감싸야 하면 리다이렉트로 파일에 받고
종료 코드를 따로 읽는다.

## §4.6 백업 경로를 닫았다

기술 §4.6은 "IndexedDB 열기 실패 → 메모리 모드, **JSON 내보내기 상시 노출**"을
요구한다. `StorageUnavailableBanner`에는 M3부터 `onBackup` 자리가 있었지만
내보낼 수단이 없어 어떤 화면도 넘기지 않았고, 버튼은 렌더되지 않았다.

편집기 배너에 연결했다. 대시보드 배너는 **연결하지 않았다** - 열린 문서가 없어
"무엇을 백업할지"가 정해지지 않는다. 라이브러리 전체 내보내기는 M8 할 일에 없다.

## 남은 경고

- **가져오기 UI가 없다.** 파일 선택기도 가져오기 대화상자도 만들지 않았다.
  `File_Structure.md`의 구현 순서표가 M8에 배정한 것은
  `features/import-json/`, `features/export-json/`, `utils/filename.ts` **셋뿐**
  이고 컴포넌트가 없다. 디자인 백서에도 JSON 가져오기 화면 명세가 없다(§2.4.7은
  Markdown 전용, M10). `JsonImportDialog/` 자리만 예약돼 있다. 데이터 경로는
  스토어 액션 두 개로 완성돼 있어 화면만 붙이면 된다.
- **내보내기 대화상자도 없다.** 디자인 §2.4.9가 요구하는 6항목 중 형식 선택,
  예상 크기, 이미지 비중, 인쇄 옵션이 M9·M11 범위다. 아직 없는 항목을 비활성
  UI로 늘어놓지 않는 것이 이 저장소 관례다.
- **`revision`이 어디서도 증가하지 않는다.** 파일명 suffix는 항상 `.r1`이다.
  올리면 INV-10의 진행 키가 갈려 기존 독자 진행이 끊기므로 개정을 언제 올릴지는
  제품 결정이다. M8이 임의로 정하지 않았다.
- **minor 관용이 실제로는 동작하지 않는다.** `assessSchemaVersion`은 `1.1`을
  `newerMinor`로 통과시키지만 `z.literal(SCHEMA_VERSION)`이 뒤에서 거부한다.
  "모르는 필드는 무시됩니다"라는 메시지가 지켜지지 않는다. 푸는 것은 스키마
  변경이라 AGENTS.md §7 STOP 대상이다. 그대로 둔다.
- **모르는 필드가 여전히 버려진다.** Zod의 strip 기본 동작이다. 보존 정책을
  M8이 정하기로 돼 있었는데, 보존하려면 문서에 미지 필드를 담을 자리가 필요하고
  그것이 곧 스키마 변경이다. **버리는 쪽을 정책으로 확정한다.** 왕복 비교 대상은
  원본 JSON 문자열이 아니라 파싱된 `GuideDocument`다.
- **`DATABASE_VERSION`은 1이고 `.upgrade()`가 없다.** M8의 마이그레이션은 문서
  `schemaVersion` 마이그레이션이지 Dexie 스키마 마이그레이션이 아니다. 인덱스를
  바꿀 이유가 없어 손대지 않았다.
- **`data-url.ts` branch 83.3%, `filename.ts` 87.5%.** 둘 다 M12 DoD 3의 90%
  대상 목록에 없다(대상은 branching·import-json·import-markdown·export-json·
  export-html). 대상인 두 모듈은 100/100과 96.4/91.5로 이미 임계를 넘는다.
- **파일 구조에 없던 파일 2개를 더했다.** `features/assets/data-url.ts`와
  `utils/download.ts`다. 둘 다 가져오기·내보내기가 **함께** 써야 하는 변환이라
  한쪽에 두면 다른 쪽이 복사한다. M9의 HTML 인라이너도 같은 것을 쓴다.
