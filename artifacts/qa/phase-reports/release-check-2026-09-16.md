## 고친 것

### 2. 미리보기 크래시

- **`src/app/AppErrorBoundary.tsx`** - 앱 전체를 두르는 오류 경계. `components/ui`가 아니라 앱 계층에 둔다. 저장 모드를 알아야 하기 때문이다. 저장소를 쓸 수 없는 브라우저에서 "새로고침하면 돌아옵니다"라고 말하면 사용자는 믿고 누르고 자료를 잃는다(검토에서 나온 지적). 메모리 모드에서는 복사를 먼저 권하고, 클립보드가 막히면 자료를 펼친다. 저장된 자료가 크래시 원인이면 "자료를 지우고 다시 시작"으로 고리를 끊는다. 제목으로 포커스를 옮긴다.
- **`MarkdownText`** - 재귀 한계(`RangeError`)만 "자료가 너무 깊다"로 안내하고, 나머지 예외는 경계로 올린다. 모든 실패를 삼키면 살균기 고장도 자료 탓으로 보인다.
- **`sanitize-html.ts`** - DOMPurify는 돌 수 없는 환경에서 **입력을 그대로 돌려준다**. 1단계가 만든 `javascript:` 링크를 조일 곳이 사라진다. `isSupported`가 아니면 던져 실패를 닫는다(검토에서 나온 지적, 이번 고침 이전부터 있던 구멍).
- `index.html`에 `noscript`.

### 3. 잘린 AI 프롬프트

- **출력 예산을 초안 크기에서 뽑는다.** 바닥 8,000, 배율 1.6, 천장 60,000. 천장은 자료 상한 60,000자를 채운 초안이 들어가는 크기이고, 그 관계를 테스트가 지킨다. `max_tokens`는 상한일 뿐이라 짧게 끝나면 비용이 늘지 않는다.
- **모델별 출력 한계 안에서 자른다.** 모르는 모델에는 8,192. 한계를 넘긴 요청은 400이 오고 "자료가 너무 깁니다"로 잘못 안내된다(검토에서 나온 지적).
- **`stop_reason`을 허용 목록으로 판정한다.** `end_turn`만 완성본이다. `max_tokens`만 막던 판은 `refusal`과 `model_context_window_exceeded`를 완성본으로 통과시켰다(검토에서 나온 지적).
- 끝까지 오지 않은 응답은 템플릿으로 떨어지고 이유를 말한다. 다시 보내도 같은 실패(키 거부 등)는 그렇다고 말한다 - `retryable`이 처음으로 화면에 닿는다.

### 4. 사실과 다른 안내

- 자료 영역 설명과 생성 버튼 옆 안내가 키 유무에 따라 전송 여부를 말한다.
- **설정 화면과 합성 경로가 같은 키 저장소 인스턴스를 쓴다.** 둘이 따로 만들면 다른 탭에서 키를 저장했거나 저장에 실패해 메모리로 내려간 뒤, 화면은 "나가지 않습니다"인데 자료가 전송된다(검토에서 나온 지적). 문구 테스트가 실제 전송 여부까지 확인한다.
- 200,000자 경고의 "자르지 않고 그대로 두니"를 지우고, 60,000자를 넘는 순간 잘린다고 미리 알린다.
- `index.html`·매니페스트·`package.json`의 v1 설명, 테마 스니펫의 v1 저장 키.
- README를 v2로 다시 썼다. 저장 위치, 전송 조건, 지우는 법, 제품정의 §7-7의 전용 키 안내.

### 5. CI·배포·줄바꿈

- `ci.yml`이 v2 게이트 11종을 돈다. e2e는 브라우저 3종이고 브라우저를 캐시한다.
- `deploy.yml` → **`release-build.yml`**. CI와 같은 게이트를 돌려 산출물만 만들고 **올리지 않는다.** 배포처가 정해지지 않아서다(차단 요소 1). 이 결정은 되돌리기 쉽고 PROGRESS 결정 로그에 사용자 확인 대기로 적었다.
- `.gitattributes`로 줄바꿈을 LF로 고정. 윈도우 새 클론에서 `format:check` 172개 파일 실패와 단위 테스트 1건 실패가 사라졌다.
- **조립기가 줄바꿈을 맞춘 뒤 센다.** 처음에는 테스트 쪽에서 맞췄는데, 그것은 제품의 어긋남을 가리고 감지기를 없앤 것이었다(검토에서 나온 지적). 되돌리고 조립기를 고쳤다.
- Vite `base`를 `./`로. 라우터가 없어 절대 base의 근거가 사라졌다.
- e2e 웹서버 예산 120초 → 240초. 차가운 러너에서 typecheck+빌드가 넘친다.

### 6. 헤더의 저장 경고

- 헤더에는 짧은 이름표만, 자세한 안내는 본문 맨 위에. 헤더는 줄바꿈된다.
- **e2e가 IndexedDB 없는 브라우저를 만들어 320px에서 경고가 화면 안에 있는지 잰다.** 기존 모바일 e2e는 가로 넘침만 보고 이 상태에 들어가지 않아 결함이 있을 때도 초록이었다.

## 남은 것

### 출시 전에 필요하다

1. **배포처 결정** (차단). 전용 도메인이나 프로젝트별 호스트. 그때까지 GitHub Pages 게시를 꺼 두기를 권한다 - 지금 공개 URL은 빈 화면이고, 푸시할 때마다 원본을 다시 게시한다.
2. **실제 API 한 번** (차단). 전용 키로 짧은 자료와 긴 자료(3만 자 이상)를 한 번씩 돌려 스트리밍·잘림 판정·요금을 확인한다.
3. **다크 테마 기본 버튼 대비 2.54:1** (major, INV-09 인접). 실측값이다.
4. **생성 실패 이유가 스크린 리더에 읽히지 않는다** (major, P7 DoD 4). 실패가 "템플릿으로 조립했습니다" 완료로 알려진다.
5. **큰 표·깊은 인용을 미리보기하면 메인 스레드가 수 초 멈춘다** (major). 크래시는 막았지만 멈춤은 남았다.
6. **저장소 열기가 거부되면 "불러오는 중입니다"에서 멈출 수 있다** (major, 추측 포함).
7. **여러 탭에서 열면 뒤처진 탭이 자료를 덮어쓴다** (minor로 조정).
8. **CSP가 없다** (minor로 조정). 키를 브라우저에 두는 앱의 방어층으로 검토할 만하다.

### 결정이 필요하다

- **시스템 프롬프트의 "자료 원문을 그대로 인용해 남긴다"는 제품정의 §6.2에 없다.** 이 한 줄 때문에 AI 출력이 초안보다 길 수밖에 없고 출력 예산이 커진다. 인용을 빼고 앱이 자료를 뒤에 붙이면 출력과 비용이 크게 준다. 제품 결정이라 손대지 않았다.
- **제품정의 문서 머리가 "초안. 사용자 승인 전"이고 §11 네 항목이 미체크다.**
- 모델 선택 UI (제품정의 §3·§6.1). 예산 함수는 모델을 받도록 해 두었다.

### 알고 남긴 것

- `eslint.config.js`의 `src/reader-runtime/**` 블록, 부르는 곳 없는 `test:coverage`, `.gitignore`의 없는 스크립트 안내 - 이번 고침 밖의 빈 게이트.

- `release-build.yml`은 e2e 웹서버와 배포 빌드에서 두 번 빌드한다.
