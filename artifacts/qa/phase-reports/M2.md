## 적대적 검토와 수정 (2차)

게이트가 통과한 뒤 4개 관점(스펙 충실도 / DoD 정직성 / 경계·불변식 / 픽스처 품질)으로 독립 검토를 돌렸다. **blocker 4건**이 나왔다.

### 가장 심각했던 것 - M1 게이트 회귀

M2 작업 중 `normalizeDocumentOrder(document: GuideDocument)` 같은 도메인 파라미터가 `verify:architecture`의 DOM 전역 검사에 걸렸다. 나는 이것을 "스코프 인식"으로 완화했는데, 구현이 **파일 단위 섀도잉 집합**이었다. 결과적으로 파라미터 하나가 파일 전체의 탐지를 껐다.

두 관점이 각각 실제 우회를 재현했다.

```text
src/domain/guide.schema.ts 끝에 아래를 덧붙여도 verify:architecture 통과(종료 코드 0)
  export const leaked = document.querySelector('body');
  const { document: d } = globalThis; export const leaked2 = d.querySelector('body');
```

게이트를 코드에 맞춰 낮춘 것이라 하네스 §0.3·§3.1 위반이다. 보수적 규칙으로 되돌리고 충돌하던 파라미터 이름 3곳을 `doc`으로 바꿨다. 회귀 테스트로 "한 함수에서 가려도 다른 함수의 실제 전역 접근을 놓치지 않는다"를 고정했다.

## 남은 경고

- Zod 기본 동작이 strip이라 모르는 필드가 파싱에서 사라진다. 우리 문서에는 그런 키가 없어 왕복은 성립하지만, 상위 minor 문서를 열었다 내보내면 손실된다. 보존 정책은 M8에서 정한다. 지금은 동작을 테스트로 고정했다.
- `tests/fixtures/assets/`와 `markdown-samples/`가 비어 있다. 하네스 §0.10은 M2부터 유지하라고 하지만 각각 M5·M10의 입력이라 그 phase에서 채운다. 그전까지 이미지 규칙은 단위 테스트의 합성 입력으로만 검증된다.
- `ImageBlock`에 장식용 플래그가 없어 `alt: ''`를 장식 선언으로 해석한다. 기술 §2.2.4의 "장식 이미지가 아닌 경우 필수"를 그대로 표현하려면 M4에서 필드 추가가 필요하다.
- vitest `dom` 프로젝트를 실행하는 스크립트가 아직 없다. M3의 `test:integration`과 함께 배선한다.
