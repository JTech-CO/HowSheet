## 왜 이 phase가 있는가

제품 방향이 바뀌었다. v1은 단계를 하나하나 입력해 분기 있는 절차 문서를 만들고
독립 실행형 HTML로 내보내는 **저작 도구**였다. v2는 자료를 붙여넣으면 한 페이지
HTML을 만드는 **프롬프트**를 써 주는 생성기다.

결과물이 HTML 파일에서 프롬프트 텍스트로 바뀌면서, 그에 딸린 개념 대부분이 함께
사라졌다. 분기 절차, 리더 런타임, 독자 진행, 가이드 문서 스키마, JSON 교환 형식이
전부 v1 고유 개념이다.

## 게이트 조정

### verify:architecture - 규칙 6종에서 5종으로

`READER_RUNTIME_BOUNDARY`와 그 전이 검사, 그리고 M7이 넣은 반공허 가드를
제거했다. 검사 대상이 사라졌으면 규칙도 사라진다.

**반공허 가드가 제 일을 했다.** `reader-runtime/`을 지우자 게이트가 "검사할
대상이 없습니다"라며 실패했다. 그 가드가 없었다면 규칙 4종이 빈 집합 위에서
조용히 통과했을 것이다. M7에서 그것을 넣은 이유가 여기서 회수됐다.

### test:security - 입력을 통째로 바꿨다

v1은 가이드 JSON의 모든 문자열 필드를 훑었다. v2에서 신뢰할 수 없는 입력은
**사용자가 붙여넣는 자료** 하나다. `tests/fixtures/xss-source.md`로 바꿨다.

기계(DOM 잔재 검사, 필수 페이로드 가드)는 그대로 쓰고 두 가지를 더했다.

- **블록 단위 검사.** 파일 전체만 보면 어느 페이로드가 샜는지 알 수 없고, 앞선
  블록이 파서 상태를 바꿔 뒤 블록이 다르게 해석되는 경우를 놓친다. 코드 펜스
  안의 빈 줄에서 자르지 않는다 - 자르면 펜스가 열린 채로 잘려 뒤 블록이 전부
  코드가 되고 페이로드가 거기 숨는다.
- **과잉 살균도 결함으로 잡는다.** 잔재 0건만 보면 전부 지워 버리는 살균기가
  만점을 받는다. 정상 내용 5종(굵게·표·코드 블록·정상 링크·인용문)이 살아남는지
  함께 본다.

## 음성 검증

7건 전부 의도대로 동작했다.

```text
2차 살균만 끄기                        → 실패 (1차만으로는 부족하다)
1차만 끄기                             → 통과 (2차만으로 충분하다)
두 겹 모두 끄기                        → 실패 (게이트가 실제 위험을 잡는다)
픽스처에서 필수 페이로드 빼기          → 실패
살균기가 모든 태그를 지우도록          → 실패 (과잉 살균 검사)
domain이 React를 import               → 실패 (DOMAIN_PURITY)
MarkdownText 밖의 dangerouslySetInnerHTML → 실패 (SANITIZE_BOUNDARY)
```

### 살균기가 죽은 코드가 아니라는 것을 확인했다

파이프라인은 두 겹이다. 1차는 remark가 `allowDangerousHtml`을 받지 않아 raw
HTML 노드를 통째로 버리는 것이고, 2차는 DOMPurify다.

처음에는 "1차가 이미 다 막으니 2차는 형식이 아닐까" 의심했다. **아니었다.**
2차만 끄자 게이트가 실패했다. `[링크](javascript:alert(1))`는 raw HTML이 아니라
**정상 마크다운 링크**라 1차를 그대로 통과하고, 그것을 막는 것은 2차뿐이다.

반대로 1차만 끄면 통과한다. 2차가 raw HTML을 혼자서도 처리한다.

정리하면 **두 겹이 각각 다른 것을 막는다.** 1차는 raw HTML, 2차는 raw HTML과
위험한 URL 모두. 어느 쪽도 지울 수 없다.

### 음성 검증이 잡은 내 실수

- 처음 변이 3건이 물지 않았고 셋 다 **변이가 잘못된 것**이었다. 살균기
  `ALLOWED_TAGS`에 `script`를 넣었지만 `FORBID_TAGS`가 이겨서 무효였고,
  `ALLOWED_ATTR_UNUSED`라는 존재하지 않는 키를 더했으며, `RULE_KINDS`에서 규칙을
  빼는 것은 그 규칙이 실제로 발동할 때만 검출되는 설계라 위반이 없으면 조용하다.
- `onerror` 페이로드를 지우는 변이가 물지 않았다. 한 줄에 `onerror`가 두 번
  나오는데(속성명과 `alert` 문자열) `String.replace`가 첫 번째만 바꿔서, 필수
  페이로드 정규식이 여전히 매치했다. 속성 전체를 앵커로 바꿔 고쳤다.

## 이번 phase에서 드러난 것

- **살균기가 도메인에 묶여 있었다.** `isAllowedUrl`이 `domain/guide.types.ts`에
  있어서 도메인 모델을 지우면 살균기가 함께 죽는다. `utils/url.ts`로 옮겼다.
  링크 프로토콜 판정은 가이드 문서의 개념이 아니라 문자열의 성질이다.
- **`local-storage`의 키 허용 목록이 리더 진행 키에 묶여 있었다.** 정확한 목록
  방식은 유지하고 v2 키만 남겼다. **접두사 규칙으로 바꾸지 않았다** - `howsheet:`로
  시작하기만 하면 통과시키면 P4의 API 키가 이 경로로 새어 들어올 수 있다.
- **살아남은 모듈의 테스트를 함께 지울 뻔했다.** `tests/unit/storage/`를 통째로
  지웠는데 그 안에 `local-storage.test.ts`가 있었다. 모듈은 남고 테스트만 사라진
  상태였다. v2 키 목록 기준으로 다시 썼다(10 케이스). 그 과정에서 `get`이
  허용되지 않은 키에 `null`을 주는 게 아니라 **던진다는** 것을 알았다 - 더 명확한
  계약이라 그대로 두고 테스트를 맞췄다.
- **의존성 4종이 통째로 쓸모없어졌다.** `dexie`(저장소 계층 삭제),
  `zod`(가이드 스키마 삭제), `react-router-dom`(화면이 하나),
  `react-hook-form`(편집기 폼 삭제). 남겨 두면 번들과 감사 대상에 계속 남는다.
