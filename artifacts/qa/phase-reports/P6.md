## 설계 판단

### 재생성은 덮지 않고 쌓는다

DoD 3은 "확인을 받거나 이전 것을 남긴다"를 요구한다. 둘 중 **남기는 쪽**을
골랐다. 확인 대화상자는 매번 한 번 더 누르게 하면서도 되돌리지는 못한다.
목록에 쌓아 두면 확인이 필요 없고, 마음에 들지 않으면 회차 버튼으로 돌아가면
된다.

상한은 열 개다. 프롬프트 하나가 수십 KB일 수 있어 무한히 쌓으면 탭이
무거워진다.

### 회차는 스토어가 붙인다

파일명이 회차를 쓰는데(DoD 2), "몇 번째로 만들었는가"는 합성기가 아니라 목록을
든 쪽이 아는 것이다. `GeneratedResult`가 `SynthesisOutcome`에 `revision`만
얹는다.

번호는 계속 올라간다. 상한에 걸려 오래된 것이 빠져도 다시 쓰지 않는다 - 같은
이름의 파일이 두 번 내려가면 브라우저가 `(1)`을 붙이고, 어느 쪽이 어느 것인지
알 수 없게 된다.

### 파일명은 자료의 첫 줄에서 만든다

v2에는 제목 필드가 없다. 자료의 첫 줄을 쓴다 - 대부분 제목이거나 첫 문장이고,
여러 자료로 만든 프롬프트를 한 폴더에 두었을 때 서로 구분된다. Markdown 제목
표시와 목록 표시를 걷어내고, 남는 것이 없으면 `howsheet-prompt`로 떨어진다.

규칙 자체(금지 문자, 제어 문자, Windows 예약 이름, 코드 포인트 기준 80자)는
v1에서 그대로 가져왔다. 확장자와 접미사만 v2의 것으로 바꾸고, 쓰이지 않게 된
`.howsheet.json` 경로는 지웠다.

### 복사 폴백은 이미 있던 것을 쓴다

`utils/clipboard.ts`와 `components/content/CopyButton`이 P0에서 살아남아
있었다. 클립보드가 막히면 대상을 선택 상태로 만들고 그 사실을 `role="status"`로
알리는 동작이 그대로 필요한 것이라 새로 만들지 않았다. 선택 대상으로 전문
상자의 `ref`를 넘긴다.

### DoD 4는 두 층으로 본다

jsdom은 레이아웃을 계산하지 않아 "가로 스크롤이 없다"를 직접 잴 수 없다.
그래서 두 가지를 나눠 두었다.

- 통합 테스트가 **줄 접기 선언이 실제로 있는지** 본다. `white-space: pre-wrap`,
  `overflow-wrap: anywhere`가 있고 고정 폭이 없어야 한다. 셋 중 어느 것을
  건드려도 물린다.
- 실제 값은 **브라우저에서 320px로** 쟀다. 4,000자짜리 한 줄을 넣고
  `documentElement.scrollWidth`가 `clientWidth`와 같은 것을 확인했다.

테스트만으로 "가로 스크롤 없음"을 주장하지 않는다.

## 이번 phase에서 드러난 것

- **`utils/filename.ts`에 소비자도 테스트도 없었다.** v1에서 넘어온 뒤로 아무도
  부르지 않아 규칙이 한 번도 검증된 적이 없었다. P6이 처음 쓰기 시작하면서
  단위 테스트 16개를 붙였고, 그중 예약 이름·코드 포인트 절단·제어 문자 순서
  세 가지는 음성 검증에서 실제로 물었다.
- **실제 브라우저에서 복사가 폴백 경로로 갔다.** 미리보기 창은 클립보드 권한을
  주지 않는다. 행복한 경로보다 이쪽이 확인하기 어려운 경로라, 우연이지만 더
  나은 증거가 됐다.
- **P5의 통합 테스트가 스토어 모양 변경을 그대로 통과했다.** `result` 하나에서
  `results` 목록으로 바뀌었는데도 16개가 다 살았다. 화면을 통해 단언한 덕이다.

## 남은 경고

- **결과 목록이 새로고침을 넘지 않는다.** `studio.store`의 자료·선택과 달리
  결과는 메모리에만 있다. 저장하면 IndexedDB가 수백 KB씩 커지는데, 프롬프트는
  다시 만들면 되는 것이라 남기지 않기로 했다. 필요해지면 P7 이후에 다시 본다.
- **회차 버튼이 열 개까지 한 줄에 늘어선다.** 좁은 화면에서 줄이 접히기는
  하지만 열 개가 쌓이면 결과 위쪽이 버튼으로 채워진다. 실제로 그만큼 쌓아 쓰는지
  보고 접이식으로 바꿀지 정한다.
- **`.md` 확장자를 쓰지만 내용이 Markdown 문법을 완전히 따르는지는 보지 않는다.**
  붙여넣기가 목적이라 렌더링 품질은 요구하지 않는다. P8의 평가셋이 문안 자체를
  본다.
- **번들은 그대로 606KB(gzip 183KB)다.** P5의 경고가 유효하다. SDK 동적 import는
  P7에서 본다.
