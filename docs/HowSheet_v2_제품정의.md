# HowSheet v2 - 제품 정의

- 상태: 초안. 사용자 승인 전이며 아직 코드에 반영하지 않았다.
- 날짜: 2026-09-08
- 대체 대상: `HowSheet_기술_백서.md`, `HowSheet_디자인_백서.md`, `HowSheet_Harness_KR.md`,
  `File_Structure.md`의 제품 정의 부분. v1은 다른 제품이므로 `docs/archive/v1/`로 옮긴다.

## 1. 무엇이 바뀌는가

**v1 (폐기)**: 사용자가 단계를 하나하나 입력해 가이드 문서를 만들고, 그것을 독립
실행형 HTML로 내보낸다. 저작 도구다.

**v2**: 사용자가 자료를 붙여넣고 버튼 몇 개로 방향을 정하면, 경량 AI가 **한 페이지짜리
HTML을 만들어 내는 상세 프롬프트**를 써 준다. 사용자는 그 프롬프트를 Claude나
ChatGPT에 붙여넣어 결과물을 얻는다. 프롬프트 생성기다.

핵심 차이는 **결과물이 무엇이냐**다. v1의 결과물은 HTML 파일이었고, v2의 결과물은
**프롬프트 텍스트**다. HowSheet는 더 이상 페이지를 렌더링하지 않는다.

## 2. 사용자 흐름

```text
[1] 자료 붙여넣기        긴 텍스트·마크다운·회의록·문서 초안
        ↓
[2] 담을 것 고르기       다이어그램 · 순서도 · 인포그래픽 · 코드 블럭 · 비교표 ...
        ↓
[3] 보일 방식 고르기     모노톤/컬러 · 학술/기술/비즈니스 · 밀도 · 타이포
        ↓
[4] 프롬프트 생성        Haiku 4.5가 [1][2][3]을 상세 프롬프트 한 장으로 합성
        ↓
[5] 복사해서 붙여넣기    Claude / ChatGPT → 단일 페이지 완성
```

4단계가 이 제품의 전부다. 1~3은 재료를 모으는 입력 폼이고, 5는 우리 밖이다.

## 3. 화면

한 페이지 안에서 끝난다. 라우팅이 필요 없다.

| 영역        | 내용                                                      |
| ----------- | --------------------------------------------------------- |
| 자료 입력   | 큰 텍스트 영역. 글자 수와 대략의 토큰 수를 함께 보여 준다 |
| 요소 선택   | 토글 버튼 그리드. 다중 선택                               |
| 디자인 선택 | 축별 단일 선택 (색 / 톤 / 밀도 / 타이포)                  |
| 생성        | 버튼 하나. 진행 중에는 스트리밍으로 프롬프트가 차오른다   |
| 결과        | 프롬프트 전문. 복사 버튼, `.md` 다운로드, 다시 생성       |
| 설정        | API 키 입력, 모델 선택, 키 삭제                           |

## 4. 요소 버튼 (무엇을 담을까)

다중 선택이다. 고르지 않으면 AI가 자료를 보고 알아서 정한다.

| 버튼       | 프롬프트에 들어가는 요구                            |
| ---------- | --------------------------------------------------- |
| 다이어그램 | 구성 요소와 관계를 인라인 SVG로. 이미지 링크 금지   |
| 순서도     | 분기와 종료 조건이 있는 절차. 위→아래 흐름          |
| 인포그래픽 | 핵심 수치를 크게. 숫자마다 단위와 출처 문구         |
| 코드 블럭  | 언어 표시, 복사 가능, 줄바꿈 보존                   |
| 비교표     | 항목 × 기준 표. 우열이 아니라 차이를 드러낸다       |
| 타임라인   | 시간 축 사건 배열. 기간과 시점을 구분               |
| 체크리스트 | 실행 가능한 항목. 완료 판정 기준을 각 항목에 붙인다 |
| 단계 절차  | 번호가 붙은 순서. 각 단계에 성공 확인 방법          |
| 용어 정리  | 자료에 나온 용어만. 새 용어를 지어내지 않는다       |
| FAQ        | 자료가 답할 수 있는 질문만                          |

## 5. 디자인 축 (어떻게 보일까)

축마다 하나씩 고른다. 기본값은 굵게 표시한 것.

- **색**: **모노톤** / 절제된 컬러(강조색 1개) / 풀 컬러
- **톤**: 학술 / **기술** / 비즈니스 / 교육 / 에디토리얼
- **밀도**: 여백 넉넉 / **표준** / 조밀
- **타이포**: **산세리프** / 세리프 / 혼합(제목 세리프)

### 5.1 생성 프롬프트가 반드시 금지하는 것

디자인 축과 무관하게 **모든** 프롬프트에 넣는다. 이것이 이 제품의 값어치다 -
그냥 "예쁘게 만들어 줘"라고 하면 어느 AI든 똑같은 결과를 낸다.

- 네온 글로우, 여러 색 그라데이션, 그라데이션 텍스트
- 글래스모피즘(`backdrop-blur`) 남용
- 장식용 이모지 제목 (`✨ 기능`, `🚀 시작하기`)
- 떠다니는 파티클·blob 배경, 마우스 추적 그라데이션
- shimmer·marquee·glitch, 호버 시 과한 확대·회전
- 폰트 3종 이상 혼용 (코드에 쓰는 고정폭은 세지 않는다 - 2026-09-15 사용자 확정)
- 외부 CDN·웹폰트·분석 스크립트 (결과물이 오프라인에서 열려야 한다)

## 6. 프롬프트 합성

### 6.1 모델

`claude-haiku-4-5` (200K 컨텍스트, 입력 $1 / 출력 $5 per MTok). 프롬프트 작문에는
충분하고 저렴하다. 설정에서 바꿀 수 있게 두되 기본값은 Haiku다.

`max_tokens`는 스트리밍으로 넉넉히 잡는다. 사고(thinking)는 쓰지 않는다 - Haiku
4.5는 `budget_tokens` 방식이고, 프롬프트 작문에 필요하지 않다.

### 6.2 우리가 Haiku에게 시키는 일

Haiku는 **결과 페이지를 만들지 않는다.** 결과 페이지를 만들 프롬프트를 쓴다.
시스템 프롬프트가 요구하는 것:

1. 붙여넣은 자료에서 실제로 근거가 있는 내용만 쓴다. 없는 사실을 만들지 않는다
2. 고른 요소마다 "무엇을 담을지"를 자료에서 뽑아 구체적으로 지정한다
3. 디자인 축을 CSS로 옮길 수 있는 수준으로 서술한다 (색상 역할, 간격 스케일, 폰트 스택)
4. §5.1 금지 목록을 결과 프롬프트에 그대로 싣는다
5. 단일 HTML 파일, 외부 요청 0건, 인쇄 가능, 320px 이상 가로 스크롤 없음을 요구한다
6. 한 페이지 분량을 넘기지 않게 범위를 좁힌다

### 6.3 키가 없을 때

**앱이 죽지 않는다.** 키가 없으면 규칙 기반 템플릿으로 프롬프트를 조립한다. 자료를
그대로 인용하고 고른 요소·디자인 축을 문장으로 펼치는 수준이라 AI가 쓴 것만
못하지만, 키 없이도 쓸 수 있고 오프라인에서 동작한다. 화면에 "AI 없이 조립한
프롬프트"라고 명시한다.

이 폴백이 있어야 첫 화면에서 키를 요구하지 않고 제품을 보여 줄 수 있다.

## 7. API 키 취급

Anthropic 공식 문서가 브라우저에서의 키 사용을 **명시적으로 위험하다고** 경고한다.
같은 문서가 "신뢰된 사용자만 쓰는 내부 도구"를 예외로 인정하고, HowSheet는 사용자가
자기 기기에서 자기 키로 자기 작업을 하는 도구라 그 예외에 해당한다. 다만 공짜로
얻는 안전이 아니므로 규칙을 못박는다.

1. 키는 **브라우저에만** 저장한다. `localStorage`, 우리 네임스페이스 아래 한 곳
2. 키는 **`api.anthropic.com` 외 어디로도** 나가지 않는다. 로그·오류 보고·분석 없음
3. 설정 화면에 위험을 그대로 적는다. "이 키는 이 브라우저에 저장됩니다"
4. **키 삭제 버튼**을 항상 보이는 곳에 둔다
5. 키를 화면에 다시 표시하지 않는다. 저장 후에는 `sk-ant-...4자리`만
6. 오류 메시지에 키를 싣지 않는다
7. 문서에 **전용 키를 새로 발급해 쓰라고** 안내한다. 다른 곳과 공유하지 않는 키여야
   유출 시 그 키만 폐기하면 된다

SDK는 `dangerouslyAllowBrowser: true`가 필요하다. 이름 그대로의 뜻이므로 그 호출
지점에 위 근거를 주석으로 남긴다.

## 10. Phase 계획

v1 하네스(M1~M12)를 대체한다. 각 phase는 v1과 같은 형식을 유지한다 - 진입조건,
할 일, 측정 가능한 DoD, 검증 명령, 주의.

| Phase | 내용                                                                  |
| ----- | --------------------------------------------------------------------- |
| P0    | v1 코드 정리. 문서 아카이브. 게이트를 새 구조에 맞게 조정             |
| P1    | 자료 입력 화면 + 자동 저장 + 살균 미리보기                            |
| P2    | 요소·디자인 선택 UI와 그 선택을 담는 도메인 모델                      |
| P3    | 템플릿 프롬프트 조립기 (키 없이 동작. INV-02·INV-06)                  |
| P4    | Anthropic 클라이언트 + 키 관리 + 설정 화면 (INV-01)                   |
| P5    | AI 프롬프트 합성 + 스트리밍 + 실패 시 템플릿 폴백                     |
| P6    | 결과 화면 - 복사·다운로드·재생성                                      |
| P7    | 접근성·모바일·인쇄 (INV-09·INV-10)                                    |
| P8    | 프롬프트 품질 평가셋. 생성된 프롬프트가 실제로 좋은 페이지를 만드는지 |

P8이 중요하다. 이 제품의 품질은 "프롬프트가 얼마나 좋은가"인데, 그건 눈으로 봐서는
알 수 없다. 고정된 자료 몇 개로 프롬프트를 만들고, 그 프롬프트로 실제 페이지를
만들어 보고, 금지 목록 위반과 자료 충실도를 채점하는 평가셋이 필요하다.
