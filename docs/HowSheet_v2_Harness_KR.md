# HowSheet v2 개발 하네스

제품 정의는 `HowSheet_v2_제품정의.md`에 있다. 이 문서는 **어떻게 진행하는가**를
정한다. v1 하네스(M1~M12)를 대체하고, 그 형식은 그대로 이어받는다.

## 1. Phase

각 phase는 진입조건, 할 일, **측정 가능한** DoD, 검증 명령, 주의로 이뤄진다.
DoD를 낮추지 않는다. 만족시킬 수 없으면 §3으로 간다.

---

### P0 - v1 정리와 v2 뼈대 (완료)

- **진입조건**: 제품 전환 승인.
- **할 일**: v1 문서 아카이브, 죽은 코드 제거, 게이트 조정, 단일 화면 뼈대.
- **DoD**: 게이트 8종 통과. 개발 서버가 뜨고 콘솔 오류 0건.
- **결과**: `artifacts/qa/phase-reports/P0.md`

---

### P1 - 자료 입력

- **진입조건**: P0 게이트 통과.
- **할 일**:
  1. 자료 입력 영역. 붙여넣기·직접 입력·지우기
  2. 글자 수와 대략의 토큰 수 표시
  3. 자동 저장. `features/autosave/autosave.service.ts`를 그대로 쓴다
  4. 저장 계층 선택과 구현 (LocalStorage로 충분한지, Dexie가 필요한지)
  5. 살균 미리보기. 원문·미리보기 전환
- **DoD**:
  1. 자료를 붙여넣고 새로고침하면 그대로 남아 있다.
  2. 저장 실패가 입력 중인 자료를 지우지 않고, 실패를 화면에 알린다. (INV-07)
  3. `tests/fixtures/xss-source.md`를 붙여넣어도 미리보기에서 스크립트가 실행되지
     않는다. (INV-05)
  4. 미리보기가 정상 마크다운(굵게·표·코드·링크·인용)을 지우지 않는다.
  5. 글자 수 표시가 실제 길이와 일치하고, 토큰 수는 근사임을 화면에 밝힌다.
  6. 자료 없이도 화면이 동작하고 다음 단계가 무엇인지 보인다.
- **검증**:

```bash
pnpm exec vitest run tests/unit/source tests/integration/source
pnpm test:security
pnpm typecheck
```

- **주의**:
  - 토큰 수를 정확한 값처럼 보여 주지 않는다. 정확한 값은 API가 세는 것이고
    여기서는 어림수다. "약"을 붙이거나 근사 기호를 쓴다.
  - 미리보기를 `dangerouslySetInnerHTML`로 그리는 곳은
    `components/content/MarkdownText/` 한 곳뿐이다. 새로 만들지 않는다.

### P2 - 요소와 디자인 선택

- **진입조건**: P1 DoD 통과. 요소·디자인 목록 확정.
- **할 일**:
  1. 요소 토글 10종 (제품정의 §4)
  2. 디자인 축 4종 (제품정의 §5)
  3. 선택을 담는 도메인 모델과 그 검증
  4. 선택 저장 (자료와 함께)
- **DoD**:
  1. 요소를 0개 골라도 진행할 수 있고, 그때 "자료를 보고 정한다"가 화면에 보인다.
  2. 디자인 축은 축마다 정확히 하나가 선택돼 있다. 선택 없음 상태가 없다.
  3. 선택이 새로고침을 넘어 유지된다.
  4. 모든 토글이 키보드로 조작되고 선택 상태가 색만으로 표현되지 않는다. (INV-09)
  5. 도메인 모델이 알 수 없는 요소·축 값을 거부한다.
- **검증**:

```bash
pnpm exec vitest run tests/unit/spec tests/integration/spec
pnpm verify:architecture
pnpm typecheck
```

- **주의**: 선택 UI를 `components/ui`에 두지 않는다. 도메인을 알아야 하므로
  `components/` 상위 계층이다. (`UI_DOMAIN_INDEPENDENCE`)

### P3 - 템플릿 프롬프트 조립기

- **진입조건**: P2 DoD 통과.
- **할 일**:
  1. 자료 + 선택 → 프롬프트 텍스트를 만드는 순수 함수
  2. 클리셰 금지 조항 삽입 (제품정의 §5.1)
  3. 결과물 요구사항 삽입 (단일 HTML, 외부 요청 0건, 인쇄, 320px)
- **DoD**:
  1. 키 없이 프롬프트가 만들어진다. (INV-02)
  2. **모든** 출력에 금지 목록 항목이 빠짐없이 들어간다. (INV-06)
  3. 같은 입력에서 같은 출력이 나온다. 시각·난수를 넣지 않는다.
  4. 고른 요소마다 그에 대응하는 지시가 출력에 나타난다.
  5. 고르지 않은 요소의 지시는 나타나지 않는다.
  6. 자료가 프롬프트에 인용되고, 잘릴 때는 잘렸다고 밝힌다.
- **검증**:

```bash
pnpm exec vitest run tests/unit/compose
pnpm typecheck
```

- **주의**:
  - 금지 목록을 문자열 하나로 뭉쳐 두고 "들어갔는지"만 보면, 목록이 비어도
    통과한다. 항목 단위로 검사한다.
  - 자료를 조용히 자르지 않는다.

### P4 - API 키 관리

- **진입조건**: P3 DoD 통과.
- **할 일**:
  1. 키 저장 모듈. `storage/` 안에 두고 `PreferenceStore`와 분리한다
  2. 설정 화면 - 입력, 마스킹 표시, 삭제, 위험 안내
  3. `verify:architecture`에 키 경계 규칙 추가
- **DoD**:
  1. 키가 `api.anthropic.com` 외 어떤 요청에도 실리지 않는다. (INV-01)
  2. 저장 후 화면에 전체 키가 다시 보이지 않는다.
  3. 삭제 버튼이 키를 실제로 지우고, 지운 뒤 상태가 "없음"으로 바뀐다.
  4. 오류 메시지·로그·콘솔에 키가 나타나지 않는다.
  5. 키를 만지는 모듈이 정확히 하나이고 게이트가 그것을 강제한다.
  6. 설정 화면이 브라우저 저장의 위험과 전용 키 발급을 안내한다.
- **검증**:

```bash
pnpm exec vitest run tests/unit/api-key tests/integration/settings
pnpm verify:architecture
pnpm test:security
```

- **주의**:
  - 키 경계 규칙을 넣을 때 **검사 대상이 실재하는지** 함께 확인한다. 대상이
    없으면 규칙이 빈 집합 위에서 돈다. (P0에서 그 가드가 실제로 물었다)
  - 키를 `PreferenceStore`의 허용 목록에 넣지 않는다.

### P5 - AI 프롬프트 합성

- **진입조건**: P4 DoD 통과.
- **할 일**:
  1. Anthropic 클라이언트. `dangerouslyAllowBrowser` 근거를 호출 지점에 남긴다
  2. 시스템 프롬프트 (제품정의 §6.2)
  3. 스트리밍 표시
  4. 실패·키 없음 시 P3 템플릿으로 폴백
- **DoD**:
  1. 키가 있으면 AI 합성이, 없으면 템플릿 조립이 돌고 화면이 어느 쪽인지 밝힌다.
  2. 네트워크 오류·429·401이 각각 다른 안내로 구분된다.
  3. 생성 실패가 입력한 자료와 선택을 지우지 않는다. (INV-07)
  4. AI 출력에도 금지 목록이 들어 있다. 빠졌으면 조립기가 덧붙인다. (INV-06)
  5. 생성 중 취소할 수 있고, 취소가 이전 결과를 지우지 않는다.
  6. `api.anthropic.com` 외 외부 요청이 0건이다. (INV-08)
- **검증**:

```bash
pnpm exec vitest run tests/unit/synthesize tests/integration/generate
pnpm verify:architecture
pnpm typecheck
```

- **주의**:
  - 모델을 임의로 바꾸지 않는다. 기본값은 `claude-haiku-4-5`다.
  - AI가 금지 목록을 빠뜨렸을 때 **조용히 통과시키지 않는다.** 덧붙이고 그
    사실을 남긴다.

### P6 - 결과 화면

- **진입조건**: P5 DoD 통과.
- **할 일**: 프롬프트 표시, 복사, `.md` 다운로드, 재생성, 이전 결과 보기.
- **DoD**:
  1. 복사가 성공하거나, 실패 시 전체 선택 폴백을 제공한다.
  2. 다운로드 파일명이 `utils/filename.ts`의 규칙을 따른다.
  3. 재생성이 이전 결과를 덮기 전에 확인을 받거나 이전 것을 남긴다.
  4. 긴 프롬프트에서 가로 스크롤이 생기지 않는다.
- **검증**:

```bash
pnpm exec vitest run tests/integration/result
pnpm typecheck
```

### P7 - 접근성·모바일·인쇄

- **진입조건**: P6 DoD 통과.
- **할 일**: 키보드 흐름, 포커스 표시, 스크린 리더 알림, 320px 대응, 인쇄 CSS.
- **DoD**:
  1. 자료 입력부터 복사까지 키보드만으로 완료된다. (INV-09)
  2. 상태가 색만으로 표현되지 않는다.
  3. 320px에서 가로 스크롤이 없고 터치 대상이 44px 이상이다. (INV-10)
  4. 생성 시작·완료·실패가 스크린 리더에 알려진다.
  5. 인쇄에서 프롬프트 전문이 잘리지 않는다.
- **검증**:

```bash
pnpm exec playwright test
pnpm typecheck
```

- **주의**: E2E를 **파이프로 감싸지 않는다.** `playwright test | tail`의 종료
  코드는 `tail`의 것이라 언제나 0이다. v1에서 이것 때문에 24건이 실패하는 채로
  두 phase가 통과했다. 리다이렉트로 파일에 받고 종료 코드를 따로 읽는다.

---

### P8 - 프롬프트 품질 평가셋

- **진입조건**: P7 DoD 통과. 채점 자동화 범위 확정.
- **할 일**:
  1. 고정 자료 5종 이상 (기술 문서, 회의록, 절차, 데이터, 개념 설명)
  2. 각 자료 × 선택 조합으로 프롬프트 생성
  3. 채점 - 금지 목록 위반, 자료 충실도, 요소 반영 여부
- **DoD**:
  1. 생성된 프롬프트에 금지 목록 위반이 0건이다.
  2. 고른 요소가 프롬프트에 모두 반영된다.
  3. 자료에 없는 사실이 프롬프트에 들어가지 않는다.
  4. 평가를 한 명령으로 돌릴 수 있고 결과가 파일로 남는다.
  5. 기준 미달이 **실패로** 보고된다. 점수만 찍고 통과하지 않는다.
- **검증**:

```bash
pnpm eval:prompts
pnpm typecheck
```

- **주의**: 이 phase의 값어치는 "돌아간다"가 아니라 "나쁜 프롬프트를 잡아낸다"다.
  일부러 나쁜 프롬프트를 넣어 평가셋이 떨어뜨리는지 확인한다.

`HowSheet_v2_제품정의.md` §8의 INV-01~INV-10이다. 매 phase의 DoD가 그중 어느
것을 지키는지 위에 적어 두었다.

## 3. 멈춤 규칙 (STOP)

### 3.1 즉시 멈춰야 하는 상황

- 같은 실패를 서로 다른 합리적 방법으로 3회 시도해도 해결되지 않는다.
- INV-01~INV-10 중 하나를 깨야만 다음 작업이 가능해 보인다.
- 백엔드, 로그인, 클라우드 저장 등 비범위 기능이 필요해 보인다.
- 키를 서버로 보내거나 제3자에게 전달해야 할 것 같다.
- 핵심 의존성의 교체 또는 major upgrade가 필요하다.
- 외부 서비스 약관, 라이선스, 보안 정책 위반 가능성이 있다.
- 데이터 유실, XSS 실행, 키 유출이 재현된다.
- 테스트·접근성 기준을 낮추고 싶은 충동이 든다.
- 큰 파일 구조 변경이나 모듈 경계 변경이 필요하다.
- 사용자가 만든 미커밋 변경과 충돌해 덮어쓸 위험이 있다.

### 3.2 멈출 때 절차

1. 더 이상 우회 코드를 추가하지 않는다.
2. `PROGRESS.md`에 증상·재현·기대/실제·시도·가설·영향 불변식을 적는다.
3. 가능하면 실패를 재현하는 테스트를 먼저 추가한다.
4. 사용자에게 보고하고 결정을 요청한다.

## 4. 절대 금지

- 실패하는 테스트를 지우거나 건너뛴다.
- 단언·임계를 약화한다. `|| true`, 무조건 `process.exit(0)`, 빈 검증 스크립트.
- 넓은 `any`나 `@ts-ignore`로 타입 오류를 감춘다.
- 살균기를 우회하거나 신뢰할 수 없는 HTML을 그대로 렌더링한다.
- API 키를 로그·오류 메시지·화면에 노출한다.
- 키를 `api.anthropic.com` 외 어디로든 보낸다.
- 생성 프롬프트에서 클리셰 금지 조항을 뺀다.
- 외부 CDN·웹폰트·분석 스크립트를 추가한다.
- 검사 대상이 없는 게이트를 통과시킨다. 대상이 사라지면 규칙도 지운다.
- E2E를 파이프로 감싸 종료 코드를 가린다.
- `.env`, 토큰, 개인 경로, 큰 임시 산출물을 커밋한다.

## 5. Phase 완료 절차

1. 해당 phase의 검증 블록을 그대로 실행한다.
2. **음성 검증** - 각 게이트를 하나씩 무력화해 의도한 테스트가 실패하는지 본다.
   물지 않으면 그 테스트는 아무것도 지키지 않는다.
3. `artifacts/qa/phase-reports/P{n}.md`에 DoD 표·실행 명령·수치·음성 검증·설계
   판단·남은 경고를 남긴다.
4. `PROGRESS.md`의 현재 phase, 결정 로그, 검증 로그를 갱신한다.
5. 커밋은 사용자가 요청할 때만 한다. 하나의 커밋은 하나의 목적만 담는다.
